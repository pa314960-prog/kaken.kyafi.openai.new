# キャッフィーの琵琶湖サバイバル

カメラの前で体を左右に動かして遊ぶ、ブラウザだけで完結するエンドレスランナーゲームです。
琵琶湖の水面を進むキャラクターを操作し、正面から迫ってくる網・釣り針・釣り糸を避け続けます。

## 公開URL

https://pa314960-prog.github.io/kaken.kyafi.sousa/

ビルドは不要です。GitHub Pages にそのまま置くだけで動きます。

## 操作方法

カメラのジェスチャーだけで一周できますが、マウスやキーボードでも操作できます。

| 操作 | カメラ | マウス | キーボード |
|---|---|---|---|
| スタート | 両手を肩より上に挙げる | 「▶ スタート」「ゲーム開始」 | Space / Enter |
| 左右の移動 | 体を左右に動かす | （非対応） | ← → |
| ストップ（中断） | （非対応） | 「■ ストップ」 | Esc |
| リトライ | 両手を肩より上に挙げる | 「もう一度」 | Space / Enter |
| 基準位置の取り直し | （非対応） | 「基準を合わせ直す」 | （非対応） |

「基準を合わせ直す」は、プレイ中に立ち位置がずれてしまったときに、**今いる場所を中央として即座に登録し直す**ボタンです。

## 画面の流れ

1. **タイトル** — 難易度を選び、「ゲーム開始」または両手を挙げて開始します。
2. **基準合わせ** — 画面中央に立って3秒待つと、基準位置と肩幅を記録します。円形のリングが進捗を示します。
3. **カウントダウン** — 3, 2, 1, GO! でゲーム開始。
4. **プレイ** — 体を左右に動かして障害物を回避します。右下の「■ ストップ」でいつでも中断できます。
5. **リザルト** — スコア・よけた数・生存時間と、難易度別のランキング（TOP5）を表示します。自己最高記録を更新すると「NEW RECORD!」が出ます。

## 難易度

難易度ごとに記録が別々に保存されます。

| 難易度 | ライフ | 障害物の速度 | 出現間隔（開始→最短） | 当たり判定 |
|---|---|---|---|---|
| やさしい | 5 | 26 | 1.90秒 → 1.05秒 | 狭め（0.85倍） |
| ふつう | 3 | 34 | 1.50秒 → 0.70秒 | 標準 |
| むずかしい | 2 | 46 | 1.15秒 → 0.48秒 | 広め（1.10倍） |

制限時間はいずれも90秒です。スコアは「生存1秒ごとに10点」＋「よけた障害物1つにつき25点」。

## 設定（画面右下のパネル）

プレイしながら調整でき、内容は `localStorage` に保存されます。

- **感度** — 小さく動かすだけで大きく動くようになります（0.6〜3.0）。
- **滑らかさ** — 大きいほどキビキビ、小さいほどぬるっと追従します（2〜14）。
- **左右反転** — 動きが逆に感じる場合にチェックを外してください。

## ローカルで動かす

ブラウザから直接 `index.html` を開くのではなく、**ローカルサーバー経由**で開いてください
（カメラ利用やモデルの読み込みには `http(s)://` での配信が必要です）。

```bash
# このフォルダで実行
python3 -m http.server 8000
```

ブラウザで `http://localhost:8000/` を開いてください。

## カメラ許可の手順

1. ページを開くと、ブラウザがカメラへのアクセス許可を求めるダイアログを表示します。
2. 「許可」をクリックしてください。
3. 許可すると姿勢推定モデルの読み込みが始まり、準備ができ次第プレイできます。
4. 左下の小窓に自分が映り、バッジが「追跡中」（緑）になれば準備完了です。

### うまく動かないとき

- 誤って「ブロック」を選んだ場合は、アドレスバー付近のカメラアイコン（鍵アイコン）から許可をやり直し、ページを再読み込みしてください。
- 他のアプリ（Zoom、Teamsなど）がカメラを使用中だと起動できないことがあります。該当アプリを閉じてから再読み込みしてください。
- 通信環境が悪いとモデルの読み込みに失敗することがあります。日本語のエラー画面が出るので、内容を確認のうえ「もう一度試す」を押してください。
- カメラがどうしても使えない環境では、← → キーだけでも遊べます。

## 画面構成

- **背景** — 琵琶湖をイメージした風景（空・雲・太陽・比良山地風の山並み・沖島風の島影・波の立つ湖面・航路のブイ）をすべて Canvas で描画しています。画像ファイルは使っていません。
- **カメラ小窓** — 画面左下の「POSE TRACKING」ドックに鏡像で表示します。検出した骨格を重ねて描き、操作に使っている肩の中心を金色の点で示します。
- **HUD** — 画面上部にスコア・残り時間・よけた数・ライフ（丸印）を表示します。

## 奥行きの表現について

障害物と波は `(x, z)` というワールド座標を持ち、`game.js` の `project(x, z)` で画面座標に変換しています。

```js
function project(x, z) {
  var s = focal / Math.max(z, 0.4);          // 1ワールド単位が何pxになるか
  return { x: cx + (x - camX) * s, y: horizonY + camH * s, s: s };
}
```

障害物は奥から**一定速度**で近づくだけで、手前に来るほど速く大きく見える加速感は遠近法から自然に生まれます。
焦点距離とカメラ高さは画面サイズから計算しているため、どの解像度でも同じ見え方になります。

## 動きを滑らかにしている仕組み

- 体の位置はレーンにスナップさせず、**連続的な座標**として扱っています。
- 平滑化と追従はどちらも**経過時間（dt）ベース**なので、フレームレートが変動しても速度が変わりません。
- 追従には**臨界減衰バネ**を使い、固定ステップ（`physicsStep`）で積分しているため、低FPSでも振動しません。
- 姿勢推定は `POSE_INTERVAL_MS` ごとに間引き、描画は毎フレーム行っています。
- 当たり判定はレーン番号の一致ではなく、**キャラクターと障害物の実際の距離**で行うため、連続移動でも公平です。
- 微動を無視するデッドゾーンを設け、静止時のふらつきを防いでいます。

## 調整パラメータ

### `game.js` の `CONFIG`（見た目・ゲーム世界）

| パラメータ | 説明 |
|---|---|
| `focalRatio` | 焦点距離 = 画面高さ × この値。大きいほど望遠になり奥行きが圧縮される |
| `horizonRatio` | 水平線の高さ（画面高さに対する比率） |
| `playerScreenRatio` | キャラクターの足元が来る画面上の位置 |
| `playerZ` | キャラクターの奥行き（ワールド単位） |
| `cameraFollow` | カメラがキャラクターを追う割合。0で固定カメラ |
| `laneCount` / `laneHalfWidth` | レーン数と航路の半分の幅 |
| `spawnZ` / `despawnZ` | 障害物が現れる／消える奥行き |
| `characterWorldHeight` | キャラクターの高さ（ワールド単位） |
| `hitHalfWidth` | 当たり判定の半幅（ワールド単位） |
| `bobAmplitude` / `bobHz` | 水面に浮かぶ上下の揺れ（平行移動のみ）の幅と速さ |
| `moveStiffness` | 追従バネの強さ。大きいほどキビキビ動く |
| `moveDamping` | 減衰比。1.0で臨界減衰（行き過ぎなし） |
| `moveMaxSpeed` | 最大移動速度（ワールド単位/秒） |
| `physicsStep` | 物理演算の固定ステップ |
| `waveRows` / `waveSpan` | 湖面の波の本数と繰り返す奥行き |
| `buoySpacing` / `buoyCount` | ブイの間隔と数 |
| `scorePerSecond` / `scorePerDodge` | 1秒あたりの加点と、1回よけたときの加点 |
| `invincibleSeconds` | 被弾後の無敵時間（秒） |

難易度ごとの値は `game.js` の `DIFFICULTY` にまとまっています。

### `main.js` の `CONFIG`（カメラ・進行）

| パラメータ | 説明 |
|---|---|
| `POSE_INTERVAL_MS` | 姿勢推定の実行間隔。描画と切り離して滑らかさを確保する |
| `CALIB_SECONDS` | 基準合わせにかける秒数 |
| `COUNTDOWN_SECONDS` | 開始前カウントダウンの秒数 |
| `HANDS_HOLD_SECONDS` | 「両手を挙げた」と判定するまでの保持時間 |
| `DEADZONE` | この範囲の微動は無視する |
| `KEYBOARD_TAKEOVER_SECONDS` | キー操作がカメラ操作より優先される時間 |
| `RANKING_MAX` | ランキングに残す件数 |

色を変えたい場合は `style.css` 冒頭の `:root` を書き換えるのが一番簡単です。

## キャラクター画像の差し替え方

標準では `assets/character.gif`（400×228・背景透過）を使用します。画像は加工せず、そのまま表示しています。

- 差し替えるときは画像ファイルを `assets/` に置き、`game.js` の `CONFIG.characterImage` をそのパスに変更してください（PNG・GIF・SVGどれでも可）。
- 背景透過を推奨します。表示サイズは高さ基準で正規化されるため、縦横比は自由です。
- ファイルが読み込めない場合は、自動的に代替のシルエット図形で動作します。エラーにはなりません。

### キャラクター画像の取り扱いについて（重要）

キャッフィーは滋賀県の公式マスコットであり、使用に関する規程があります。本実装ではもっとも安全側のルールとして、キャラクター画像に対して以下の操作のみを行っています。

- 平行移動（`translate`）
- 縦横比を保った拡大縮小（`scale(s, s)` で縦横同一の値のみ使用）
- 表示・非表示（フェードを含む）

以下はコード内でキャラクター描画に一切使用していません。

- 回転（`rotate`）、傾き（`skew`）、左右反転（`scaleX(-1)` 等の非対称スケール）
- 縦横比を変える拡大縮小
- 色の変更（`filter` の `hue-rotate` / `saturate` / `invert` 等）
- 画像の一部だけを切り出す描画
- パーツ分割して個別に動かす処理（ひげだけを揺らす等）
- キャラクター画像の上に他の図形・文字・エフェクトを重ねる処理

カメラ映像は鏡のように左右反転して表示しますが（`#input-video.mirrored` の `transform: scaleX(-1)`）、この反転は**カメラ小窓のDOM要素にのみ**適用されます。ゲーム本体のキャンバスとは別要素なので、キャラクター画像には反転が一切かかりません。さらに `game.js` の `drawCharacter()` は描画直前に `base()` で座標系を基準へ戻しています。

被弾時の演出（画面のふちが赤く光る）は画面全体のビネット効果として実装しており、キャラクター画像そのものには重ねていません。

## 技術構成

- 姿勢推定: [MediaPipe Tasks Vision](https://ai.google.dev/edge/mediapipe/solutions/vision/pose_landmarker) の `PoseLandmarker`（CDN経由で読み込み）
- 描画: Canvas 2D（透視投影・最大3倍の高DPI描画・通常画面で1.5倍スーパーサンプリング）
- カメラ: 対応機種では最大1080p / 60fpsを優先（非対応時は自動的に利用可能な画質へ調整）
- 追従: 臨界減衰バネ + 固定ステップ積分
- 効果音: Web Audio API による合成（音声ファイル不要）
- 書体: Google Fonts（Zen Maru Gothic / Outfit）
- フレームワーク不使用、素のJavaScript
- 記録・設定の保存: `localStorage`
